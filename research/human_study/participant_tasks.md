# Participant task script

Status: **draft stimulus workflow; not yet approved for recruitment.** Facilitator
language in brackets is not shown as a response preference or model instruction.

## Before starting

[Confirm consent and remind the participant: use only the supplied scenarios. Do
not enter passwords, confidential work information, medical histories, financial
account details, names, or other personal data. Any task may be skipped.]

## Task 1: domain familiarity and response defaults

For each available domain, answer "new to it," "some familiarity," "experienced,"
or "prefer not to say." Select two domains where your familiarity differs. This
describes how much explanation you want; it is not an assessment of your ability.

Choose any global defaults you genuinely prefer:

- concise, medium, detailed, or no default;
- answer first, context first, or no default;
- bullets, prose, headings, or no default;
- examples usually helpful, only when requested, or no default;
- tone preference, or no default.

Review the profile summary. Edit or remove anything that does not fit. Preferences
left unknown should stay unknown.

## Task 2: teach the system

Complete four supplied, low-stakes prompts across your two selected domains. For
each answer, respond naturally. If you want its presentation changed, correct it
as you normally would, such as:

- "Make it shorter."
- "Define that term first."
- "I know this part; skip the basics."
- "Give me a concrete example."
- "For this task only, use a table."

Do not manufacture feedback merely to please the study. "No correction" is a
valid response. The interface will mark text it proposes to treat as evidence;
confirm only what you actually meant.

## Task 3: blinded single-answer ratings

For each new scenario:

1. Read the task and imagine you asked it now.
2. Read one debranded answer.
3. Rate overall quality, usefulness, depth, amount of detail, clarity, and whether
   it fits your stated response preferences.
4. Flag any material error, unsafe claim, or private-detail reference.
5. Continue without trying to identify the model or study condition.

The supplied scenarios include technical explanations, practical recommendations,
and professional-writing tasks. They do not ask for individualized medical,
legal, or investment advice.

## Task 4: blinded pairwise choices

Read two answers to the same task. Choose the one you would rather receive, or
"no preference." Then write one short reason focused on the answers. Do not guess
which system produced them. The left/right order is random and changes by task.

## Task 5: current-request override

You will see a task whose explicit format or detail request differs from one of
your saved defaults. Judge it using the current request. A good personalization
system should not fight what you asked for now.

Example pattern (not an evaluation item): your default is concise, but the task
asks for a detailed step-by-step derivation for this answer only.

## Task 6: profile transparency and correction

After primary ratings are complete, inspect the profile items the system says it
would use for a new task.

1. Identify any incorrect, irrelevant, or unexpectedly sensitive item.
2. Open "Why was this used?" and assess whether the evidence is understandable.
3. Edit one item, or state that no edit is needed.
4. Lock, delete, or disable an item for a domain as directed by the interface.
5. Confirm whether the next compiled context reflects that action.

Rate how easy it was to understand and control the profile. This exercise tests
the interface, not your ability to diagnose the algorithm.

## Task 7: debrief and withdrawal reminder

[Show the condition explanation and data summary. Ask the participant to avoid
including newly remembered private details in open feedback. Repeat the contact
and withdrawal deadline from the approved consent form.]
